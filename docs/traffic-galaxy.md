# Traffic Galaxy

Replaces the Overview Traffic Mix tile with a compact session galaxy. The five source buttons reveal session counts and shares on hover, focus or tap. Supabase session counts are the sole numerator and denominator; Cloudflare visits remain separately labeled in detailed analytics. Google Search combines tagged organic and referrer-inferred organic sessions. Unknown channels fall into Other. Inconsistent or missing responses display unavailable rather than zero.

Daily detail uses PR #34's existing `migrations/admin-traffic-daily-sources.sql`; do not apply a duplicate migration. It preserves the existing admin access check, ACLs and conversion logic and adds daily counts only. No analytics records or unrelated tables are changed. Missing pre-collection/retention dates are marked outside coverage; observed zero days remain zero. The first tracked/retained date and today are labeled partial. Date filters and the existing polling cadence are preserved.

Validation: 480 tests passed, 4 existing skips. The database regression test applies both existing traffic migrations in local PGlite, checks admin/non-admin/anonymous permissions, and reproduces a read-only production aggregate (date-shifted within retention). The fixture contains only daily channel counts, with no identifiers. Browser checks at 1440, 820 and 390 pixels verified a 210px tile, no horizontal overflow, interaction, strict content security policy, and reduced motion. Other overview metrics in screenshots are representative preview values, not live business totals.

The candidate Worker code was compared structurally with the live Worker: no changed or added declarations. The preview version preserves all 53 live bindings, runtime settings and cron schedules. Official logo/tagline assets and payment, Quick Read, registration and email code are untouched.

Limitations: consent, blockers and missing referrers limit coverage; sessions are not unique people. Google organic includes inference and cannot reliably separate untagged paid traffic. No previous-period uplift is displayed. Staging lacks the existing admin traffic schema, so database validation uses local PGlite plus read-only production aggregates rather than installing unrelated staging infrastructure. Existing Supabase advisor findings are unchanged; the admin traffic function deliberately keeps its existing internal authorization guard.
